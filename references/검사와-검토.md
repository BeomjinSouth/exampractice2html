# 검사와 검토

## 순서

1. 교사용에서 학생용을 만든 뒤 `python -X utf8 "<스킬>/scripts/sheet.py" check "<활동지 폴더>"`를 실행한다. 반환값은 0(오류 없음), 1(수정 필요), 2(도구 실패)다.
2. 출력된 `검사/모아보기.png`와 `검사/모아보기-흑백.png`, 학생·교사 쪽 PNG를 열어 직접 확인한다. 교사용 PDF의 전체 쪽 번호에는 학생 쪽이 포함된다. 화면 풀이가 켜졌다면 `검사/화면-폰.png`(390×844), `검사/화면-태블릿.png`(1024×768)와 `검사/학생-채움-NN.png`도 각각 열어 잘림·겹침과 입력한 답의 인쇄 상태를 확인한다. 채움 인쇄 그림은 모아보기에 넣지 않는다.
3. 자동 검사는 계산의 정오나 문장의 적절성을 보증하지 않는다. 문항을 따로 풀어 정답·풀이·배점·그림과 문장의 일치까지 검산하고 `검사/검토.md`에 실제 확인 내용을 기록한다.
4. 고쳤으면 학생용을 다시 만들고 `check`를 다시 실행한 다음, 새 결과를 보고 `검토.md`를 다시 쓴다. `status`는 설치된 엔진 지문과 학생·교사 모든 쪽 그림을 확인한다. 다섯 관문이 모두 통과하면 출력된 전달 문안을 바탕으로 경로와 확인 범위를 알리고 마지막 줄은 그대로 둔다. `검사/`에는 정답을 포함한 보고가 있으므로 학생에게 함께 배포하지 않는다. 구성이나 plan 도구가 없으면 구성 검증은 확인 불가로 표시한다. 다만 편집본을 원본으로 인정하지 않은 경우 조립 관문에는 원고와 build 기록이 필요하다.

| 오류·경고 | 히스토그램·도수분포다각형의 음수 도수, 정수가 아닌 도수 또는 서로 다른 계급 폭 | 음수는 고치고, 소수 도수와 계급 폭은 자료의 뜻을 확인한다. `y_label`에 상대도수·비율을 적으면 정수 경고는 생략한다. |

`check`는 연동된 학생용을 `?nosync` 주소로 열어 검사 중 기록이 전송되지 않게 한다. 연동 정보의 `sheet-sync` 메타에 있는 프로젝트 URL은 외부 자원 오류로 보지 않지만, 다른 원격 그림·글꼴·스크립트는 허용하지 않는다. 검사 브라우저는 오프라인으로도 실행한다.

`check`는 기존에 자동 저장된 답을 지운 다음 두 HTML을 A4 보기로 검사·인쇄한다. 화면 풀이가 켜진 학생용은 두 크기의 빈 풀기 화면, 정답표의 각 자리별 정답·오답 판별, 답을 채운 A4 인쇄를 추가로 검사하고 끝에 답을 다시 지운다. 채움 인쇄에는 정답표의 정답과 함께 서술 칸마다 두 줄 글(`검사 서술 첫째 줄`/`둘째 줄`), 그리기 칸에 획 하나, 이름 칸에 `검사`를 넣는다. 그다음 활동지를 **다시 열고 확인 창의 `이 기기에서 내가 쓰던 답 열기`를 누른 뒤** 자동 저장된 답이 그대로 돌아오는지 비교한다. 그 상태로 인쇄해 PDF에 서술 두 줄이 남았는지 센다. 넣은 입력 종류와 결과는 `report.json`의 `interactive_check.filled_inputs`·`filled_restored`·`filled_text`에 남는다. `reveal: 없음`이면 판별 자체 시험은 생략하지만 채움 인쇄는 만든다.

`report.json`은 두 엔진 보고, 판정 목록, 생성 파일과 검사 시각을 담는다. `interactive_check`에는 화면별 크기·가로 넘침, 가능한 정답·풀이·비교를 연 폰 화면의 `filled_screen`, 판별 자체 시험을 한 자리 수(`grading_tested`)와 판별 결과(`passed`·`failed`·`skipped-reveal-none` 등)를 기록한다. `filled_inputs.from_answer_table`은 판별하지 않았더라도 정답표 값으로 채운 자리 수다. 펜 층을 숨긴 PDF와 대조한 픽셀 수는 각각 `student.print_pen`과 `interactive_check.filled_print_pen`에 남는다. 이 비교는 눈에 띄는 손실을 찾는 검사이므로 엷은 선이나 일부 가림은 쪽 그림에서도 확인한다. 실행 중 실패하면 예전 보고는 `검사/_이전/`에 보관해 현재 검사로 오인하지 않게 한다. 교체되거나 남는 옛 화면·쪽 그림과 PDF도 같은 폴더로 이동한다. 검사 도구는 Chrome 또는 Edge가 필요하며 `SHEET_BROWSER`에 실행 파일을 지정할 수 있다. 시험에서 `SHEET_TEST_PROFILE` 또는 `SHEET_TEST_TMP`를 지정하면 브라우저 프로필을 보존·재사용할 수 있다.

## 자동 검사가 못 잡는 것

`answer-leak`은 교사용에서 지워진 정답 문자열이 학생용에 남았는지만 본다. 원래 학생에게 보이는 글이 앞 문항의 답을 알려 주는 경우는 잡지 못한다. 검토할 때 아래를 직접 확인하고 `검토.md`에 적는다.

- **앞 답이 뒤에 보이는지:** 학생용을 처음부터 끝까지 읽으며 뒤 문항·개념 상자·표·O·X 문장·힌트·점검표에 앞에서 구하게 한 식·값·용어가 있는지 본다. 화면 풀이에서는 쪽을 나눠도 뒤 내용이 다 보인다.
- **상황의 수 범위:** 개수처럼 자연수인 양에 음수·소수를 넣거나 점을 선으로 잇게 하지 않았는지, 수 전체로 넓힐 때 전환을 밝혔는지 본다.
- **휴대폰 화면:** `화면-폰.png`에서 좌우 나눔이 위아래로 쌓였을 때 발문이 ‘왼쪽·오른쪽’으로 가리키지 않는지 본다.
- **종이로만 풀 때:** 인쇄본만으로 모든 문항을 할 수 있는지 본다. 값을 바꿔 비교하는 탐구에 `print` 그래프가 있는지, 화면 전용 동작(‘놓으세요’)을 지시하지 않았는지.
- **답 칸 크기:** 한 줄 답에 큰 칸이 붙지 않았는지(짧은 답의 `grow`), 서술 칸이 예시 답안 분량에 맞는지.

## 검토.md 양식

아래는 **형식 예시**다. 실제 확인 전 복사한 문구만으로 통과 처리하지 않는다. 학생 PDF의 모든 쪽과 교사용 PDF의 모든 쪽을 각각 확인해 번호를 적는다. 교사용 번호는 PDF 전체 쪽 번호를 쓴다. 검토 시각은 `report.json`보다 뒤여야 한다.

```markdown
판정: 통과
검수: 자체
```

`## 화면 확인`에서는 `filled_inputs`에 나온 채움 종류와 `grading_tested`의 판별 시험 수를 따로 적는다. `reveal: 없음`은 정답표 값으로 채워 인쇄하되 판별 시험은 생략한다.

`status`의 1단계와 전달 문안에 원고 경고가 코드별 건수로 나온다. 경고가 남아 있으면 `## 원고 경고` 아래에 코드마다 `- 코드: 고침 — 까닭` 또는 `- 코드: 그대로 둠 — 까닭` 한 줄을 쓴다. 코드가 없는 경고는 `uncoded`로 묶인다. 4단계 관문은 이 절과 코드별 판단·까닭을 확인한다. 원고 경고가 없으면 이 절은 생략한다.

화면 풀이가 켜진 학생용은 `## 화면 확인` 절이 있어야 `status`의 검토 관문을 통과한다. 화면 풀이가 꺼져 있으면 이 절은 필수가 아니다. 실제 본 그림과 확인 결과를 적는다.

`검수`는 실제 검수에 맞게 `자체` 또는 `독립`을 쓴다. 이상이 있으면 첫 줄에 `판정: 보류`를 쓰고 수정·재검사한다. 쪽 수에 맞지 않는 예시 번호는 실제 번호로 바꾼다.
