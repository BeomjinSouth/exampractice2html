# A4 지면 기준

근거: 만든 이의 HWPX 활동지 스킬(`pbj-worksheet-hwpx`)의 조판 기준 1~9장을 HTML 계약에 맞게 요약했다.

지면 모양과 쪽 나눔은 엔진이 맡는다. 활동지를 만드는 쪽에서는 `구성.json`의 내용과 블록을 고른다.
현재 요청과 학교 지정 양식이 먼저다. 작도 공간과 읽기 쉬운 글자가 쪽 채움 비율보다 중요하다.

## 용지와 본문

| 항목 | 자동 적용되는 기준 | 구성에서 정할 것 |
| --- | --- | --- |
| 용지 | A4 세로, 210×297mm | 유형 `meta.kind` |
| 1단 여백 | 좌우 10mm, 위아래 5mm | `meta.columns: 1` |
| 1단 본문 | 190×287mm | 내용과 item 묶음 |
| 1단 상자·표 | 폭 188.0mm, 좌우 바깥 여백 1mm씩 | 필요한 블록 선택 |
| 2단 수업형 | 사방 10mm, 본문 190×277mm | `meta.kind: "수업"`, `meta.columns: 2` |
| 2단 상자·표 | 단 폭에서 1.2mm를 뺀 폭 | 각 단에 들어갈 item 크기 |
| 머리말·꼬리말 | 지면용 여백 0mm | 인쇄 대화상자의 머리글·바닥글 끄기 |

- `meta.columns: 2`는 수업형에서만 허용한다.
- 1단의 188mm를 2단 안쪽 표의 고정 폭으로 적용하지 않는다.
- 페이지 크기와 여백을 채우려고 임의의 빈 문단이나 작은 표를 끼워 넣지 않는다.

## 글꼴·크기·색

| 역할 | 기본 모양 | 줄 간격과 색 |
| --- | --- | --- |
| 평가·연습 머리표 1행 제목 | 고딕 12pt | 120%, 검정 |
| 평가·연습 머리표 2행 제목 | 고딕 13pt | 120%, 검정 |
| 평가·연습 상황·대화와 답 칸 | 명조 10pt | 160%, 검정 |
| 평가·연습 발문 | 고딕 9.5pt | 114%, #202020; 긴 연습 발문은 150% 참고 |
| 평가 답안표 라벨 | 명조 9.5pt 굵게 | 160%, #17365D |
| 라벨 속 쓰기 안내 | 명조 9pt | 160%, #17365D |
| 연습 답안표 라벨 | 명조 8pt | 160% |
| 수업형 | 모두 고딕; 본문 10pt 기준 | 160% 참고 |
| 수업형 글이 많은 참고 예 | 고딕 9pt | 140% 참고 |

- 엔진은 평가·연습의 머리표·발문에 `Sheet Sans`, 상황·답안표·라벨에 `Sheet Serif`를 쓴다.
- 수업형은 모두 `Sheet Sans`를 쓴다. `meta.kind`를 고르면 역할이 정해진다.
- 조립 때 Noto Sans KR와 Noto Serif KR를 잘라 내장한다. 글꼴을 찾지 못하면 대체 글꼴을 쓰고 경고한다.
- 크기·간격 수치는 원본 기준 또는 참고값이다. 구성에 없는 글꼴·크기 필드를 임의로 만들지 않는다.
- 한 문서의 발문 모양은 통일하고, 한 문장을 임의의 줄바꿈으로 잘라 넣지 않는다.

## 세로 간격

| 사이 | 기준 | 처리 |
| --- | --- | --- |
| 머리표 → 첫 상자 | 4.1~9.1mm | 엔진의 블록 배치 |
| 같은 문항 안 상자·발문·답안표 | 대체로 3~4mm | 문항을 하나의 item으로 묶기 |
| 문항과 다음 문항 사이 | 기본 8.2mm | item 사이 자동 간격 |
| 한 칸에서 쪽 맞춤이 빠듯할 때 | 문항 사이 4.7mm | 엔진이 그 칸에서 다시 맞춰 봄 |

문항 안의 간격이 문항 사이 간격보다 작아야 묶음이 잘 보인다.

## 블록별 모양과 구성

| 대상 | 자동 모양·크기 | 구성에서 정할 것 |
| --- | --- | --- |
| 평가 머리표 | 188×22.5mm, 2행×5열; 점수·학생 확인 칸 | `meta.kind: "평가"`와 확인된 머리 정보 |
| 연습 머리표 | 188×22.5mm, 2행×1열; 점수 칸 없음 | `meta.kind: "연습"`과 확인된 머리 정보 |
| 수업 머리표 | 제목과 단원·학번·이름; 짝 행 선택 가능 | `meta.kind: "수업"`, 필요하면 `meta.pair` |
| 두 번째 장 이름 띠 | 1단에서 1행×2열, 폭 188mm; 열 너비 60mm와 128mm, 높이 9.9mm | 두 번째 장 첫 item에 `nameband.label` |
| 안내 상자 | 라벨 열 약 25.1mm와 안내 글 | `notice.label`, `notice.lines` |
| 상황 상자 | 1단 기준 글 64~69% : 그림 31~36%; 그림 없으면 한 칸 | `situation.lines`, 선택적으로 `title`, `figure`, `note` |
| 그림 두 장 | 2행×2열; 위에 그림, 아래에 캡션; 1단 기준 각 열 94mm | `figures.items`의 그림 두 개와 각 `caption` |
| 그림 한 장 | 가운데 정렬, 원본 비율 유지 | `figure`의 그림 객체와 선택 `caption` |
| 발문 | 자동 번호와 왼쪽 정렬 문단 | `question.text`, 필요하면 `number: false` |
| 평가 답안표 | 라벨 열 25.1mm, 나머지는 답 칸 | `answer.rows`의 `label`, `points`, `lines` 등 |
| 연습 답안표 | 라벨 열 46.1mm, 나머지는 답 칸 | `answer.rows`의 내용과 답 |
| 수업 답안표 | 라벨 열 30mm, 나머지는 답 칸 | `answer.rows`의 내용과 답 |
| 단계 기록 | 번호 ①②…와 기록 칸 | `steps.columns`, `rows`, `answers`, 선택 `lines` |
| 수업 질문 상자 | 제목 줄과 흰 답 칸; 수업 2단형 | `ask.tag`, `text`, `lines`, `answer`, 선택 `grow` |
| 모눈·좌표평면 | 설정한 실제 mm 크기로 계산해 그림 | `grid.mode`, `unit_mm`, 범위 또는 칸 수 |

- 머리표는 `meta`로 자동 생성한다. 직접 `header` 블록을 만들지 않는다.
- 수업 답안표의 라벨 열 30mm는 이번 HTML 기준이다.
- `nameband`는 두 장으로 분리 배부할 때 쓰며, 실제 두 번째 장 첫머리인지 확인한다.
- 그림 객체의 `width_mm`은 인쇄될 폭이다. 길이나 각을 옮길 자료의 축척은 따로 검산한다.
- 모눈선은 0.1mm 회색 `#999`, 좌표축은 0.3mm 검정이다.

## 답 칸 높이

기본 본문 10pt·줄 간격 160%에서 `answer.rows[].lines`로 정하는 높이다.
엔진은 `5.64 × lines − 1.1`mm를 적용한다. 본문 크기가 바뀌면 그 배율도 반영한다.

| `lines` | 기본 높이 | 시작점의 예 |
| --- | --- | --- |
| 2 | 10.2mm | 짧은 판단 |
| 3 | 15.8mm | 한두 문장 |
| 5 | 27.1mm | 더 긴 설명 |
| 7 | 38.4mm | 긴 답 또는 그림 공간의 참고 |
| 8 | 44.0mm | 사례와 설명 |
| 9 | 49.7mm | 긴 사례와 설명 |

- 답안표의 `answer.rows[].lines`는 2~30이며 기본값은 3이다. `ask.lines`는 직접 지정한다.
- 답 칸을 7mm 미만으로 만들지 않는다.
- 조판용 `lines`와 학생의 손글씨 줄 수는 다르다. 예시 답안의 실제 분량을 별도로 검산한다.
- 답안표의 `kind: "draw"`는 줄 수 대신 `height_mm`으로 필요한 작도 높이를 준다.
- 라벨이 길면 그 행은 내용 때문에 기본 답 칸 높이보다 높아질 수 있다.
- 긴 서술 칸은 `grow: true`로 남는 높이를 받을 수 있게 한다.

## 쪽 나눔과 남는 높이

| 엔진이 하는 일 | 구성에서 확인할 일 |
| --- | --- |
| 한 item을 쪽 밖으로 나누지 않고 다음 쪽에 담는다 | 발문·상황·답안표 등 함께 볼 것을 한 item으로 묶는다 |
| 2단에서는 한 item을 단 밖으로 나누지 않는다 | item이 빈 단에도 들어가는지 확인한다 |
| `break: true`인 item을 새 칸에서 시작한다 | 1단은 새 쪽, 2단은 새 단임을 확인한다 |
| 남는 높이를 `grow` 칸에 기본 높이 비율로 나눈다 | 늘려도 되는 서술 칸에만 `grow: true`를 둔다 |
| 쪽 또는 단의 약 98.5%를 목표로 늘리고 넘치면 줄인다 | 목표 범위 95~99.5%와 답안·작도 공간을 함께 살핀다 |

- `grow` 칸이 없거나 내용이 너무 크면 목표 채움에 이르거나 넘침을 피한다고 보장할 수 없다.
- 빈 쪽이나 빈 단에도 들어가지 않는 item은 넘침으로 표시되므로 묶음과 내용을 다시 조정한다.
- 마지막 쪽은 90% 미만이면 경고한다. 수치만 맞추기보다 작도 가능 공간과 가독성을 우선한다.
- 넘치거나 지나치게 남으면 다음 순서로 조정한다.
1. 늘려도 되는 서술 칸의 `grow`를 지정하거나 해제한다.
2. 예시 답안과 손글씨 분량을 확인하며 `lines`를 조정한다.
3. `break`로 문항을 재배치한다. 2단에서는 새 단으로 이동함을 기억한다.
4. 마지막으로 상황 그림의 `width_mm`을 5~20% 범위에서 조정한다.
- 길이·각을 옮기는 작도 자료 그림을 조정했다면 가로세로 비와 인쇄 축척을 다시 검산한다.
- 쪽을 채우려고 문항이나 안내 글을 늘리지 않는다.

## 선·색과 인쇄

| 항목 | 기준 |
| --- | --- |
| 일반 표 테두리 | 0.12mm 검정 실선 |
| 머리표 위·아래 | 0.7mm 이중선 |
| 평가·연습 채우기 | 없음 |
| 수업형 채우기 | 표·질문 제목 `#DAEEF3`, 상황 상자 `#F8F8F8` |
| 흑백 인쇄 | 색이 사라져도 선·기호·글이 구분되어야 함 |
| 인쇄 배율 | 실제 크기 100%; 용지에 맞춤 금지 |

- 엔진의 `@page`는 A4와 `margin: 0`을 지정한다. 브라우저 여백 메뉴가 반드시 ‘없음’이어야 하는 것은 아니다.
- 브라우저 인쇄 대화상자에서 머리글·바닥글은 끈다. 출력 미리보기에서 쪽과 잘림을 확인한다.
- 용지에 맞춤으로 축소하면 작도 자료의 길이가 바뀐다. 실제 출력된 축척을 확인한다.
