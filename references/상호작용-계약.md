# 상호작용 계약 (2판, 유지보수용)

[구조와 계약](구조와-계약.md)의 인쇄용 활동지(1판)를 넓힌다. 1판의 약속(A4 쪽 짜기, `#sheet-src`, 교사용/학생용, check·status 관문)은 그대로 두고, 이 문서는 **학생이 화면에서 직접 푸는 활동지**와 **더 다양한 블록·테마·그림**을 더한다. 두 문서가 다르면 이 문서가 우선한다.

## 0. 목표

- 한 파일이 두 가지로 쓰인다: **A4 인쇄본**(1판 그대로)과 **풀기 화면**(학생이 입력·조작하고 정답을 확인하는 화면).
- 학생은 HTML에 직접 쓴다: 빈칸·답 칸·표 칸 입력, 선택지, O·X, 짝짓기, 순서 맞추기, 수직선·좌표평면에 점 찍기·직선 긋기, 막대 높이 정하기, 펜으로 그리기, 이름 칸.
- 정답 확인(자동 판별), 단계 힌트, 시도 뒤 정답·풀이 보기, 풀이 영상, 맞힌 개수, 슬라이더 탐구.
- 다단은 **최대 좌우 2단 한 겹**: 쪽 전체 2단(`meta.columns: 2`, 모든 종류에서 허용하되 정본 관례상 수업형에서 쓰고 연습·평가는 사용자가 요청할 때) 또는 블록 안 좌우 나눔(`split`). 둘을 겹치지 않는다.
- 더 예쁜 테마(`산뜻`)와 그림 에셋(이미지 모델로 만든 삽화·스티커). 수학 도형·그래프·통계 그래프는 계속 **코드로 계산해 그린다**.
- 인쇄 결과는 1판과 같은 품질을 지킨다.

## 1. meta 추가 필드

| 필드 | 값 | 기본 |
| --- | --- | --- |
| `interactive` | `true` / `false` — 학생용에 입력·정답 확인을 넣을지 | `수업`·`연습` `true`, `평가` `false` |
| `reveal` | `"시도 후"`(그 item에서 `확인`을 한 번 누른 뒤 정답·풀이 보기 열림) · `"바로"`(처음부터 열림, 자습용) · `"교사만"`(맞음/틀림만, 정답·풀이 없음) · `"없음"`(입력만, 판별·정답 없음: 제출용) | `"시도 후"` |
| `theme` | `"정본"`(1판 흑백 양식) · `"산뜻"`(색·카드·아이콘, 흑백 인쇄 가능) | `수업` `"산뜻"`, `연습`·`평가` `"정본"` |
| `accent` | `"하늘"` · `"민트"` · `"주황"` · `"보라"` (산뜻 테마 강조색) | `"하늘"` |

`interactive: false`이면 학생용은 1판과 같다(입력·판별 자료 없음).

## 2. 두 가지 보기

- 엔진이 실행 중 `<html data-view="a4">` 또는 `data-view="solve"`를 붙인다(저장할 때 지운다).
- **a4 보기 = 인쇄 모습**이다. 화면 전용 장치(확인 단추·힌트·판별 표시)는 a4 보기에서 보이지 않는다. 그래서 a4 화면과 인쇄가 같은 높이로 짜인다. a4 보기에서도 입력할 수 있다. 채운 빈칸과 이름 칸은 글자에 맞춰 늘어나며, 채운 빈칸의 기호는 자리를 차지하지 않는다. 여러 줄 답은 기존 답 칸 안에서 줄을 바꾼다.
- **solve 보기**: 쪽을 나누지 않고 `#sheet-src`의 item을 순서대로 `<main id="sheet-flow">`에 옮겨 놓는다. 본문 폭 최대 820px, 가운데 정렬. 폭 390px에서도 가로 넘침이 없어야 한다: 표의 `<col>` mm 폭은 같은 비율의 %로 바꾸고(되돌릴 값 보관), 그림·SVG는 `max-width:100%`, `split`·2단은 폭 720px 미만에서 위아래로 쌓는다. 입력 글자는 16px 이상(휴대폰 확대 방지).
- 클래스 약속: `.ws-solve-only`는 solve 보기에서만 보임, `.ws-print-only`는 a4 보기와 인쇄에서만 보임.
- 학생용 + interactive: 처음 열면 solve(폭 900px 이상이면 마지막으로 고른 보기를 기억해 씀). 교사용: a4. 교사용 도구 막대에 `학생 화면 미리보기`(정답 끄고 solve, 학생과 같은 입력·판별)와 `교사 화면으로`.
- 인쇄는 언제나 A4: `인쇄` 단추는 `await view('a4')` 뒤 `window.print()`, `beforeprint`에서는 동기로 a4를 짜고 `afterprint`에서 원래 보기로 돌아간다.

## 3. 학생 입력

엔진이 실행 중에 입력 장치를 만든다(원본 HTML에는 없다). 학생 입력 자리는 조립 때 `data-slot="<item id>.<번호>"`를 받는다(번호는 item 안 문서 순서로 1부터, 문서 안 유일). 머리표 이름 칸은 `data-slot="head.<칸 이름>"`.

| 자리 | 화면 | 인쇄 |
| --- | --- | --- |
| 빈칸 `.ws-blank[data-slot]`(표의 `td.ws-fill` 안 빈칸 포함) | 빈칸 너비 그대로의 한 줄 입력 | 입력한 글자(없으면 빈 밑줄) |
| 답 칸 `.ws-ans[data-slot][data-kind="text"]` | 칸을 덮는 여러 줄 입력(줄 간격 5.64mm, 자동 줄바꿈) | 입력한 글 |
| 그리기 칸 `.ws-ans[data-kind="draw"]`, `figure[data-pen="1"]` | 펜(마우스·터치·펜), 지우개, 모두 지우기 | 그린 선 |
| 선택지 `ol.ws-choices[data-slot]` | 누르면 동그라미(`data-multi="1"`이면 여러 개) | 고른 번호에 동그라미 |
| O·X, 짝짓기, 순서, 점·직선, 막대, 점검표 | 10절의 블록 | 고른·놓은 상태 |
| 이름 칸 `.ws-name-slot[data-slot]` | 한 줄 입력 | 입력한 글자 |

- **자동 저장**: 입력은 바로 `localStorage`(키 `pbj-sheet:<sheet-build source_sha256>:<role>`)에 저장되고 다시 열면 되살아난다. 모든 저장소 접근은 try/catch(막혀 있으면 조용히 건너뜀).
- **답을 넣어 저장**(학생용 도구 막대): 현재 값을 각 자리의 `data-value`(JSON 문자열)에 써 넣은 사본을 `<제목> (내 답).html`로 내려받는다. 열 때 `data-value`가 자동 저장보다 먼저 적용된다.
- **내 답 지우기**: 확인 창 뒤 모든 입력·판별 표시·자동 저장을 지운다.
- 값 형식(자동 저장·`data-value`·`sheet.answer()` 공통): 글자 자리 = 문자열, 선택지 = 번호 배열, O·X = `"O"`/`"X"`, 순서 = 토큰 배열, 짝 = `{왼쪽토큰: 오른쪽토큰}`, 점 = `[[x,y],…]`(수직선은 `[x,…]`), 직선 = `[[x1,y1],[x2,y2]]`, 막대 = 수 배열(빈 막대 `null`), 그림 = `{"strokes": [[[x,y],…],…]}`(칸 크기에 대한 0~1 비율), 점검표 = 불리언 배열.
- 제출·계정·서버 전송은 없다.

- `chart` 자료: `bar`·`line` = `labels[]` + `values[]`, `histogram`·`polygon` = `bins[]`(경계값, 길이 n+1) + `values[]`(n), `scatter` = `points[[x,y]…]` + `x: [a,b]` + `y: [a,b]` + `x_step?`. `teacher: true`면 막대·점·선을 교사용에만 그린다(학생은 빈 축). `plot: {answer: [수…], snap?}`(bar·histogram만)이면 학생이 막대 높이를 눌러 정한다.
- `grid.plot.answer`: `points` = `[[x,y]…]`, `line` = `"2*x+1"`(일차식) 또는 두 점 `[[x1,y1],[x2,y2]]`. `snap` 기본 1. 정답 점은 snap의 배수여야 한다.
- `pen: true`는 `grid`·`numberline`·`figure`에 쓸 수 있다(그리기만, 판별 없음).
- item 필드 `hints: ["…"]`(1~3): solve 보기에서 `힌트 1`, `힌트 2` 단추로 차례로 연다. 인쇄에 나오지 않는다.
- `teacher.solutions[].video?: {url, start?}`: 풀이 보기 안에 풀이 영상.
- 답안표 행 새 필드: `check?`(`"auto"` 기본 · `"number"` · `"text"` · `"off"`), `accept?: ["…"]`(다른 정답). 빈칸은 `{{㉠|+5;;5}}`처럼 `;;`로 다른 정답을 잇는다(첫째가 교사용 표시).
- 선택지는 `answer`가 배열이면 여러 개 고르기.
- 중첩 규칙: `split` 안에 `split` 금지, `meta.columns: 2`이면 `split` 금지(plan 오류).

## 5. 정답 확인(자동 판별)

### 5.1 판별 종류(`data-check-kind`)

조립 도구가 정한다.

| kind | 대상 | 정하는 법 |
| --- | --- | --- |
| `number` | 빈칸·답 칸·단계 칸 | 정답 평문이 `num()`으로 수가 됨 |
| `text` | 빈칸, 또는 `check: "text"`·`accept`가 있는 답 칸 | 빈칸: 수가 아니고 평문 12자 이하 |
| `open` | 그 밖의 글자 자리 | 자동 판별 안 함. 예시 답안과 스스로 비교 |
| `choice` `ox` `order` `match` `points` `line` `bars` | 해당 블록 | 블록 필드 |
| `draw` `self` `name` | 그리기·점검표·이름 칸 | 판별 안 함 |

- 답안표 행 `check: "auto"`: 수면 `number`, `accept`가 있으면 `text`, 아니면 `open`. `"off"`는 언제나 `open`.
- `open` 자리: 학생이 글자나 숫자를 한 자 이상 쓰면 `예시 답안과 비교` 단추가 열리고(`reveal`이 `시도 후`·`바로`일 때), 교사 풀이의 `rubric`이 있으면 점검 목록으로 함께 보인다. ‘원점’처럼 짧아도 완결된 답을 글자 수로 막지 않는다.
- 판별 결과는 `true`(맞음)·`false`(틀림)·`'review'`(확인 필요)·`null`(판별 안 함·빈칸) 넷이다. `'review'`는 `text` 자리에서만 나온다 — 정규형과 허용 정답이 모두 어긋나면 틀림이 아니라 ‘확인 필요’로 보인다(같은 뜻의 다른 표현을 도구가 다 알 수 없으므로). `number`·`choice`·`ox`·`order`·`match`·`points`·`line`·`bars`는 엄격하게 `true`/`false`.

### 5.2 정규화(파이썬과 JS가 똑같이 — 시험 자료 `tests/engine/answer-cases.json`)

`norm(s)`: NFKC → `−‒–—―`(U+2212, U+2012~2015)를 `-`로 → `⁄`(U+2044)를 `/`로 → 모든 공백 제거 → 소문자 → 끝의 `.`·`。` 제거.

`num(s)`: `t = norm(s)` → 앞의 `[a-z]=` 하나 제거(`x=2`) → 끝의 단위 하나 제거(`answer-cases.json`의 `units`, 긴 것부터, 단위만 남으면 제거 안 함) → 전체를 감싼 괄호 한 겹 제거 → 앞 `+` 제거 → `^-?[0-9]{1,3}(,[0-9]{3})+(\.[0-9]+)?$`면 쉼표 제거 → `^-?[0-9]+$`·`^-?[0-9]+\.[0-9]+$`·`^-?[0-9]+/[0-9]+$`(분모 0 제외) 중 하나면 기약분수 `"p"` 또는 `"p/q"`(q>0), 아니면 `null`. 숫자는 `[0-9]`만 쓴다.

`number_parts(s)`: `num`과 같은 과정에서 떼어 낸 단위를 함께 돌려준다 — `[수, 단위]`(단위가 없으면 `""`, `도`는 `°`로 통일), 수가 아니면 `null`. `num(s) = number_parts(s)[0]`.

`text_candidates(s)`: `t = norm(s)`. `t`에 `=`가 정확히 하나 있고 양쪽이 비어 있지 않으며 `< > ≤ ≥ ≠`가 없으면 `[t, 오른쪽=왼쪽]`, 아니면 `[t]`(빈 값이면 `[]`). `text` 자리는 이 후보 가운데 하나라도 허용 정답과 같으면 맞음이다(`y=2x`와 `2x=y`).

정답 쪽은 표기 원본을 `plain()`으로 평문으로 바꾼 뒤 같은 함수를 쓴다(조립 도구와 엔진 편집기 모두; 시험 자료 `plain`, 명령 이름 뒤 공백은 먹는다): `$` 제거, `\frac{a}{b}`·`\dfrac` → `a/b`, `\times`→`×`, `\div`→`÷`, `\le`→`≤`, `\ge`→`≥`, `\ne`→`≠`, `\pi`→`π`, `\sqrt{a}`→`√a`, `\text{…}`·`\mathit{…}`·`\mathrm{…}` → 안의 글자, `\,` `\ ` `~` → 없앰, `\left` `\right` 없앰, 나머지 중괄호 없앰, `**` 없앰, `\$ \{ \}`는 글자.

정규형(kind별): `number` = `num`, `text` = `norm`, `choice` = 고른 번호 오름차순 `,` 연결(`"1,3"`), `ox` = `"o"`/`"x"`(입력 `O ○ o`→o, `X × x`→x), `order` = 학생이 놓은 순서의 토큰을 `,`로, `match` = 왼쪽 표시 순서대로 `l1:r3,l2:r1,…`(모두 이어야 판별), `points` = 각 점 `num(x),num(y)`(수직선은 `num(x)`)을 문자열 정렬해 `;`로, `line` = 두 점을 지나는 직선 `ax+by=c`의 정수 `a,b,c`(분모를 없애고 최대공약수로 나누며 a, b 중 처음 0이 아닌 것이 양수; 같은 두 점은 판별 불가), `bars` = 각 막대 `num`을 `,`로(빈 막대가 있으면 판별 안 함).

점·막대 값은 `snap`의 배수로 맞춘다: `k = Math.round(v / snap)`, 값 = `Number((k * snap).toFixed(6))`을 문자열로 만든 뒤 `num`.

### 5.3 파일에 넣는 방식

- 파일마다 무작위 `salt`(16바이트 hex): `<meta name="sheet-salt" content="…">`.
- 판별 해시: `data-check-hash="h1,h2,…"`(허용 정답마다), `h = sha256_hex(utf8(salt + "|" + kind + "|" + 정규형))`. 학생 파일에는 정답의 평문이 없다.
- 단위: `number` 정답(또는 허용 정답)에 단위가 있으면 그 자리에 `data-check-unit="1"`을 붙이고, 단위가 있는 값마다 `수@단위`(예 `2@분`)의 해시를 더 넣는다. 학생이 단위를 쓰지 않으면 수만 비교하고, 쓰면 `수@단위`가 허용 해시에 있어야 맞음이다(정답 `2분`에 `2`·`2분` 맞음, `2시간` 틀림). `data-check-unit`이 없으면 학생 단위는 무시한다.
- 정답 표시·풀이는 한 덩어리 JSON을 난독화해 넣는다: `<script type="application/octet-stream" id="sheet-reveal">base64(json_utf8 XOR key)</script>`, `key = sha256(utf8(salt + "|reveal"))`의 32바이트를 반복. JSON: `{"slots": {"q1.1": {"answer_html": "…"}}, "items": {"q1": {"solution_html": "…", "rubric": ["…"], "video": {"yt": "ID", "start": 0}}}}`. `answer_html`은 표기를 렌더한 HTML(수식은 MathML).
- `reveal: "교사만"`이면 `#sheet-reveal`을 넣지 않는다. `reveal: "없음"`이면 해시와 `#sheet-reveal`을 넣지 않는다(`data-check-kind`는 두되 엔진은 판별하지 않음).
- **난독화는 보안이 아니다.** 개발자 도구를 다룰 줄 아는 학생은 풀 수 있다. 전달 보고에 한 줄로 밝힌다. `평가`가 `interactive: false` 기본인 까닭이다.
- 교사용에도 같은 `salt`·해시·`#sheet-reveal`을 넣는다(학생 화면 미리보기용). 학생용·교사용은 같은 salt를 쓴다.
- 엔진은 SHA-256과 base64 풀기를 **직접 구현**한다(`file://`에서 `crypto.subtle`에 기대지 않는다).
- 조립 도구는 `검사/정답표.json`을 남긴다(학생 파일에는 넣지 않는다, 10.2의 `data-check`에서 만든다): `{"salt": "…", "slots": [{"slot": "q1.1", "kind": "number", "right": <값 형식의 정답>, "wrong": <틀린 값>}]}`. 자동 판별 자리마다 하나. `wrong`은 정답이 아닌 그럴듯한 값(수는 +1, 글자는 끝 글자를 바꾼 것, 선택지는 다른 번호, 순서는 두 개를 바꾼 것 등)이며 어떤 허용 정답과도 같지 않아야 한다.

### 5.4 화면 동작(solve 보기)

- 자동 판별 자리·힌트·풀이가 있는 item 끝에 도구 줄: `확인`(그 item의 자동 판별 자리 모두) · `정답 보기` · `풀이 보기`(정책에 따라) · `힌트 n` · 결과 `2/3 맞음`(확인 필요가 있으면 `· 확인 필요 1`).
- 자리마다 맞으면 초록 ✓, 틀리면 "다시 생각해 봐요", 확인 필요면 주황 "예상한 답과 달라요. 같은 뜻이면 선생님께 확인받아요." 값을 고치면 그 자리 표시가 사라진다.
- `시도 후`: 그 item의 어느 칸에도 답이 없으면 `확인`은 시도로 치지 않고 "먼저 답을 써 보세요."만 보인다(학생 기록도 보내지 않는다). 답이 있는 칸만 판별한다. `정답 보기`는 답을 쓴 칸의 정답만 보이고, `풀이 보기`는 그 item의 응답 칸(펜 그리기 칸 제외)이 모두 채워졌을 때 열린다(점 찍기는 정답 점 수만큼). `바로`·`교사만`·`없음`의 동작은 1차와 같다.
- `정답 보기`: 자리 옆에 `answer_html`을 보인다(입력은 그대로). `풀이 보기`: item 아래에 `solution_html`(+ 풀이 영상).
- 도구 막대에 `맞힌 수 m / 자동 판별 n`.
- 판별 표시·정답·풀이는 a4 보기와 인쇄에 나오지 않는다(`.ws-solve-only`).

## 6. 테마 `산뜻`

- `<html data-theme="산뜻" data-accent="하늘">`, CSS는 `assets/engine/theme-fresh.css`를 `<style id="sheet-theme">`로 넣는다(정본이면 넣지 않는다).
- 머리표: 제목 큰 띠(강조색 옅은 바탕), 단원·이름 칸 둥근 칸. `heading` 강조색 태그 + 아이콘, `callout` 아이콘 + 옅은 바탕, 답 칸·표 둥근 모서리 얇은 선, 발문 번호 강조색 원.
- 아이콘: `data-icon="pencil|bulb|search|check|video|chart|puzzle|star|warn|book|calc|flag"`. 테마 CSS가 데이터 URI SVG를 `mask-image`로 그린다(외부 파일 없음). 정본에서는 아이콘을 그리지 않는다.
- 흑백 인쇄: 바탕은 밝기 92% 이상, 글자는 짙게. 강조색은 선·태그·번호에만.
- 정본은 1판 그대로. 새 블록의 정본 모양은 흑백 선 위주(sheet.css).

## 8. check 추가

- 학생용(interactive)을 390×844와 1024×768로 solve 보기에서 열어 `검사/화면-폰.png`, `검사/화면-태블릿.png`(전체 페이지). `report().overflow_x > 1`이면 오류.
- **판별 자체 시험**: `검사/정답표.json`의 자리마다 학생용에서 `sheet.answer(slot, right)`가 `true`, `sheet.answer(slot, wrong)`가 `false`여야 한다. `sheet.slots()`의 자동 판별 자리 수와 정답표 자리 수가 같아야 한다. 어긋나면 오류.
- 유출: 1판 규칙 + 학생용 원문에 정답표의 정답 평문(4자 이상)이 있으면 오류. `#sheet-reveal` 안(난독화)은 허용.
- 외부 자원: `.ws-video`의 `data-yt`와 표시용 `https://youtu.be/…`만 허용.
- 인쇄 PDF 전에 `await sheet.view('a4')`. `report().print_leaks > 0`(a4 보기에서 보이는 `.ws-solve-only`·판별 표시 수)이면 오류.
- 학생용에 정답표의 `right`를 모두 넣고, 자동 판별이 아닌 서술 칸(`open`, `.ws-ans`)에는 두 줄 글, 빈칸 `open`에는 `검사`, 그리기 칸(`draw`)에는 획 하나, 이름 칸에는 `검사`를 넣는다. 그 상태로 **다시 열어**(`Page.reload`, 자동 저장만으로 복원) `values()`가 넣은 값과 같은지 비교하고(다르면 `filled-restore-failed` 오류), a4 인쇄해 `검사/학생-채움-01.png …`를 만든다. PyMuPDF가 있으면 PDF 글자에서 서술 칸 두 줄이 모두 보이는 칸 수를 세어 서술 칸 수보다 적으면 `filled-print-missing` 오류. 결과는 `report.json`의 `interactive_check.filled_inputs`·`filled_restored`·`filled_text`.
- 뒤 문항 식 유출: 정답표의 `text` 정답 가운데 등호가 하나인 식(좌우 바꾼 꼴 포함)이 뒤 item의 학생용 글(정답·교사 전용·화면 단추 제외, 힌트 포함)에 그대로 있으면 `later-answer-shown` 경고. 낱말·수 답은 뒤에서 용어·자료로 계속 쓰이므로 자동으로 보지 않는다.

## 9. 엔진 API 추가

`window.sheet`에 더한다(1판 API 유지).

- `view(mode)`: `"a4"`·`"solve"`, Promise(다 짠 뒤 풀림). `view()`는 현재 보기.
- `slots()`: `[{slot, kind, item, auto}]`(`auto` = 자동 판별 자리).
- `answer(slot, value)`: 그 자리에 값을 넣고(화면에도 반영) 판별 결과 `true`/`false`/`null`(판별 안 하는 자리·`reveal: 없음`)을 돌려준다. ‘확인 필요’는 `false`로 돌려준다(검사 도구의 정답·오답 시험 계약 유지). Promise가 아니라 바로 값. 네 가지 결과는 내부 `core.verdicts()`(`{slot: true|false|'review'|null}`, 학생 기록 전송용)에서 본다.
- `values()`: `{slot: 값}`. `score()`: `{checked, correct, total}`. `clearAnswers()`.
- `report()`에 `view`, `interactive`, `slots_total`, `print_leaks`, `overflow_x`(문서 가로 넘침 px)를 더한다.

### 10.2 자리 공통 속성

`data-slot`, `data-check-kind`, `data-check-hash`(자동 판별 자리만), `data-value`(저장된 학생 값, 선택). 1판의 `data-src`·`.ws-key` 규칙은 그대로(학생용에서 지움).

**교사용 전용 `data-check`**(학생용에서 `data-src`처럼 속성째 지움): 자동 판별 자리마다 JSON `{"mode": "auto"|"number"|"text"|"off", "accept": ["…"], "right": <값>, "wrong": <값>}`. `mode`·`accept`는 구성.json의 `check`·`accept`(빈칸은 `;;` 뒤 대안), `right`·`wrong`은 3절 값 형식. 쓰임:

- `검사/정답표.json`은 build와 derive가 **교사용 HTML의 `data-check`에서** 만든다(그래서 브라우저에서 고친 교사용에서도 다시 만들 수 있다).
- 교사가 브라우저 편집기로 빈칸·예시 답안 글자를 고치면, 엔진은 그 자리의 `data-check-kind`·`data-check-hash`·`data-check`와 `#sheet-reveal`의 `answer_html`을 같은 규칙(5.1~5.3, JS의 `plain`·`norm`·`num`)으로 다시 만든다. item 복제·삭제·이동 뒤 저장할 때 `data-slot` 번호를 item마다 다시 매긴다(정답표는 다음 derive 때 새로 만들어진다).
- JS의 표기 렌더러는 빈칸 `{{기호|가;;나|너비}}`에서 첫째 정답 `가`만 교사용 정답으로 보인다.

## 12. 학생 기록 연동(Supabase)

목표: 교사가 스킬로 만든 학생용 HTML **파일만** 나눠 주면, 학생이 풀며 확인·제출한 기록이 교사의 Supabase에 자동으로 쌓이고, 교사는 **교사용 HTML의 `학생 기록`** 화면에서 본다. 서버 코드·배포·학생 계정은 없다.

### 12.1 교사 설정(한 번)

- `assets/supabase/schema.sql`: 교사가 Supabase SQL 편집기(또는 Supabase MCP)에서 한 번 실행한다.
  - `public.sheet_records`(id identity, created_at default now(), sheet_id text, sheet_title text, build text, client_id text, student jsonb, event text check in ('check','submit'), item text, score jsonb, answers jsonb, verdicts jsonb; 글자 길이·크기 제한 check).
  - `public.sheet_teachers(email text primary key)`.
  - RLS 켬. `anon`은 `sheet_records`에 **insert만**(select·update·delete 없음). `authenticated`는 `auth.jwt()->>'email'`이 `sheet_teachers`에 있을 때만 select. 인덱스 `(sheet_id, created_at desc)`.
- 교사 계정: Supabase 대시보드 Authentication에서 이메일·비밀번호 사용자를 만들고 `insert into sheet_teachers values ('교사 이메일')`. 공개 회원가입은 꺼 두기를 권한다.
- `sheet.py sync config --url https://<프로젝트>.supabase.co --key <publishable(anon) 키>`: 사용자 설정 파일(Windows `%LOCALAPPDATA%\pbj-html-sheet\sync.json`, 그 밖 `~/.config/pbj-html-sheet/sync.json`)에 저장. `sync show`, `sync test`(시험 행 insert가 201/204인지), `sync schema`(SQL 출력), `sync off`(설정 지움). 키는 **publishable/anon 키만** 받는다(`service_role`·`sb_secret_`이면 거절).

### 12.2 조립

- `meta.sync`: `true`(기본: 설정 파일이 있고 `interactive`일 때) / `false`. `meta.sheet_id`: `new`가 만들어 넣는 고정 id(소문자·숫자·`-`, 32자 이하). 없으면 build가 제목 해시로 만들고 경고한다.
- sync가 켜지면 두 파일 `<head>`에 `<meta name="sheet-sync" content='{"v":1,"url":"…","key":"…","table":"sheet_records","sheet":"<sheet_id>","title":"…"}'>`. 정답은 넣지 않는다.
- 저장소(README·examples)에는 어떤 설정값도 들어가지 않는다.

### 12.3 학생용 엔진

- 이름: 머리표에서 본인 식별 칸(`head.학년`·`head.학번`·`head.이름`·`head.성명`·`head.반`·`head.번`·`head.학급`·`head.번호`)만 `student`로 보낸다. **짝 이름과 학번 등 `head.짝-*` 칸은 보내지 않는다.** 이름이나 성명 칸이 비어 있으면 보내지 않고 solve 보기 위쪽에 이름을 먼저 쓰라고 알린다.
- 보내는 때: item `확인`을 누를 때(`event: "check"`, `item`), 도구 막대 **`선생님께 제출`**(`event: "submit"`, 확인 창 뒤). 행: `sheet_id, sheet_title, build(source_sha256 앞 12자), client_id(기기·활동지별 무작위, localStorage), student, event, item, score(score(), 활동지 전체), answers, verdicts({slot: true|false|'review'|null})`.
- 보내는 범위: `check` 행의 `answers`·`verdicts`는 **그 문항 자리(`<item id>.`로 시작)만** 담는다. 다른 문항의 초안은 보내지 않는다. `submit` 행은 머리표 칸을 뺀 모든 답을 담는다. 대기열에 남은 예전 형식의 행도 보낼 때 본인 식별 정보와 해당 답 범위만 남긴다.
- 전송: `fetch(url + "/rest/v1/sheet_records", {method: "POST", headers: {apikey: key, Authorization: "Bearer " + key, "Content-Type": "application/json", Prefer: "return=minimal"}, body, keepalive: true})`. 실패하면 localStorage 대기열에 넣고 다음 전송·`online` 때 다시 보낸다(최대 50건).
- 표시: 도구 막대에 `기록: 보냄 ✓ 14:02` / `보내지 못함 — 다시 시도`. solve 보기 첫 줄에 본인 식별 정보와 답을 보내는 사실, `확인` 때는 해당 문항의 답·판별 결과와 활동지 전체 맞힌 수, `선생님께 제출` 때는 모든 답·판별 결과와 맞힌 수를 보낸다는 사실, 짝 칸의 정보는 보내지 않는다는 사실을 안내한다. a4 보기·인쇄에는 나오지 않는다.
- 보내지 않는 경우: `sheet-sync` 없음, `data-role="teacher"`(학생 화면 미리보기 포함), 주소에 `nosync`가 있음(`?nosync` 또는 `#nosync`), `reveal: 없음`이어도 보낸다(제출용).

### 12.4 교사용 `학생 기록` 화면

- 교사용 도구 막대 `학생 기록`(sync가 있을 때만): 전체 화면 패널. 이메일·비밀번호 로그인(`POST /auth/v1/token?grant_type=password`, 토큰은 sessionStorage에만) → `GET /rest/v1/sheet_records?sheet_id=eq.<id>&order=created_at.desc&limit=5000`.
- 묶음: 학생 신원(이름·성명, 반, 번·학번을 NFC·공백 정리한 값)이 같으면 한 학생이다. client_id(기기)로 묶지 않는다 — 공용 기기에서 여러 학생이 써도 따로 보이고, 한 학생이 기기를 바꿔도 한 줄이다.
- 판: 교사용 `sheet-build`의 `source_sha256` 앞 12자와 기록의 `build`가 모두 있고 같을 때만 현재 판이다. 둘 중 하나가 없거나 다르면 다른 판으로 취급한다. 학생별 상태·맞힌 수·자리별 정답률은 현재 판 기록으로만 계산한다. 다른 판만 있으면 `다른 판에서 제출` 또는 `다른 판 기록만 있음`으로 구별한다.
- 상태: 현재 판의 가장 최근 `submit` 행이 있으면 그 제출본의 답·판별·시각을 보여 주고 `제출`, 그 뒤에 현재 판의 `check` 기록이 있으면 `제출 후 수정`(상세 보기에 "제출 뒤 바뀐 답이 있습니다(마지막 기록 시각)"). 현재 판 제출이 없으면 현재 판 `check` 행들을 시간순으로 자리별 병합한 진행 중 답과 `미제출`.
- 표: 학생별 마지막 기록 시각, 상태, 점수(맞음/판별), 자동 판별 자리마다 ✓/✗/?(확인 필요)/빈칸 열(머리에 문항 번호), 다른 판의 앞 6자와 기록 시각을 표시한다. 상세에서는 다른 판 기록마다 답을 그대로 보여 주되 현재 판의 정답과 비교하지 않는다. 그리기·점·직선 답은 SVG로 표시하며 같은 판은 교사용 칸 크기·좌표를 쓰고, 다른 판은 저장된 좌표를 상자에 맞춘다. 다른 판의 점·직선 종류는 현재 자리 기준으로 추정하며, 자리가 없으면 좌표를 점으로만 표시하고 직선 여부를 알 수 없다고 밝힌다. 어느 경우든 저장된 답도 확인할 수 있다. 점 찍기와 펜을 함께 쓰는 칸의 펜 획은 `values()`에 없어 전송되지 않는다.
- 위쪽 요약: 학생(이름 기준) 수, 현재 판 제출 수, 기기 수(서로 다른 client_id), "같은 이름·반·번호는 한 학생으로 묶습니다", 현재 판 자리별 정답률(‘확인 필요’는 정답률에서 빼고 따로 센다). `새로 고침`, `CSV 내려받기`(UTF-8 BOM, `판` 열 포함: 현재 판은 학생별, 다른 판은 기록별로 내보내고 다른 판의 정오·점수는 비움), `로그아웃`. 최근 5,000행까지만 불러온다.
- 로그인 실패·권한 없음(교사 이메일이 `sheet_teachers`에 없음)·연결 실패를 각각 한국어로 알린다.

### 12.5 check·시험

- check는 학생용을 `?nosync`로 연다(전송하지 않음). 외부 자원 검사는 `sheet-sync`의 `url` 한 곳을 허용한다.
- 엔진 시험은 `fetch`를 가짜로 바꿔 전송 행·대기열·재전송·학생 기록 패널(가짜 응답)을 확인한다.
- 개인정보: 학생 이름과 답이 교사의 Supabase에 저장된다. 학교의 개인정보 규정·학생 안내는 교사의 몫이며, README와 SKILL.md에 한 줄로 밝힌다.
